# 有界上传热点块缓存

## 目标与边界

完整源和下载中共享来源共用上传读取边界。先记录重复块、不同块、随机 seek、边下载边上传的读取/校验次数与延迟，再实现成功读取合并和有界 LRU，最后用相同工作负载对照。

- [x] 建立可重复的本地基线与计数 fixture，记录结果。
- [x] Client 级缓存预算，按发布实例隔离；同块在途读取合并，数据与证明通过 Arc 共享。
- [x] 按保留的数据/证明字节限制 LRU；0 禁用保留，仍合并同时发生的读取；过大块不保留。
- [x] 命中仍检查可用状态与文件元数据；元数据变化清除旧项并重新验证，源错误不缓存；下载目标新增块可导致保守失效。
- [x] 等待者可取消；读取启动后即便原请求取消，也保留阻塞任务、读取/连接额度直到结束；关闭清除所属项并禁止完成后回填。
- [x] 补齐失败、淘汰、重复/不同内容、源变更、取消/关闭和真实联机回归，更新双语文档。

默认预算为 16 MiB（上限 256 MiB），Builder 显式配置 upload_cache_bytes。预算仅涵盖缓存保留的数据和证明；在途读取、连接持有的发送/重传数据和 DataChannel 缓冲各受已有并发限制，不承诺进程总 RSS 等于缓存预算。

缓存只保存已验证内容快照，不以缓存替代来源可用性检查。Unix 额外使用 ctime 辅助识别恢复 mtime 的修改；其他平台仅检查标准元数据，命中不重新读取磁盘字节，不能承诺发现所有保留元数据的外部修改。缓存返回的字节仍是此前校验通过的内容。

## 实现记录

- 缓存集中在扁平模块 `upload_cache.rs`，Client 共用总预算，每次发布拥有独立命名空间；完整源与下载中共享接入相同边界。低层非托管 `serve_file` 和同步读取 API 保持原有路径。
- LRU 计入数据、证明容量和条目基础结构；淘汰不撤销发送/重传仍持有的 Arc。HashMap 分配、在途任务及连接缓冲不属于该保留预算。
- 同块读取合并到一个任务；0 预算只关闭保留，仍合并在途请求。错误不保留、不克隆，实际读取者保留原有类型化错误，等待者重试或收到关闭状态；未增加 TransferError 变体。
- 命中检查同样受读取并发预算约束。下载来源同时检查数据文件与证明记录文件，新增块可能保守失效；失效按请求惰性清理。关闭先清空并禁止回填，再结束上传任务。
- 下载存储原有读写锁仍存在，本项减少重复读取/校验，没有拆分存储锁。Unix 元数据行为已本机验证，Windows 适配未做运行时验证。

## 测量

每项 8 个工作者、共 128 次请求，调试构建、热文件系统。计数是来源读取及校验调用次数，不是物理磁盘 I/O 次数；下载中共享包含提交新块成本，耗时仅用于本机对照，不代表端到端网络吞吐。

初始实现前基线：同块 128 次/145 ms，不同块 128 次/187 ms，重复 seek 128 次/192 ms，下载中共享 128 次/1008 ms。

最终同次运行对照：

| 工作负载 | 无缓存读取次数 / 耗时 | 16 MiB 缓存读取次数 / 耗时 |
| --- | --- | --- |
| 同块热点 | 128 / 101 ms | 1 / 4 ms |
| 全部不同块 | 128 / 108 ms | 128 / 110 ms |
| 重复随机 seek | 128 / 93 ms | 17 / 19 ms |
| 下载中共享 | 128 / 1019 ms | 16 / 389 ms |

复现：`cargo test -p q2q source_read_workloads --offline -- --ignored --nocapture`。无缓存模式绕过保留与合并，作为原有读取路径对照；不对耗时设断言。
